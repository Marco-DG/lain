\chapter{Generics and compile-time evaluation}
\label{sec:14-generics}
\index{generics}
\index{compile-time evaluation}
\index{comptime}

\section{Overview}
\label{sec:gen.overview}

\pnum
Lain implements genericity through compile-time function evaluation (CTFE).
Generic types and functions accept \textit{type parameters} (declared as
\lain{name type}), and a generic type also accepts \textit{compile-time value
parameters} (declared as \lain{name T} with \lain{T} an integer type).  The
compiler evaluates them at compile time and monomorphizes the result.  There is
no type erasure and no runtime polymorphism.

\begin{note}
  \textbf{Implementation status.}  The reference compiler implements the
  \emph{core} of this chapter and monomorphizes it: generic \lain{func}s with
  \lain{type} parameters (bound by inference from a value argument or by an
  explicit type argument), and generic types written
  \lain{type Name(T type) \{ ... \}}, including compile-time value parameters of a
  type (const generics, \lain{type Buf(N usize)}).  The remaining constructs below are
  \emph{planned} and not yet accepted --- \lain{comptime \{ ... \}} expression
  blocks and the \lain{func}-returning-\lain{type} spelling; each is flagged at
  its section, and is presently reported as \diagcode{E100}.  (\lain{comptime if},
  \S\,\ref{sec:gen.comptime-if}, \emph{is} available.)
\end{note}

\section{Type parameters}
\label{sec:gen.type-params}
\index{type parameter}

\pnum
A parameter declared \lain{name type} is a type parameter.  Types are
implicitly compile-time — the \lain{comptime} keyword shall \emph{not}
precede a type parameter.  At every call site, the argument shall be a type
expression known at compile time.

\begin{laincode}
func identity(T type, x T) T {
    return x
}

func main() i32 {
    var n = identity(int, 42)       // T = int, given; monomorphized
    var s = identity("hi")          // T = u8[:0], inferred; a separate monomorphization
    return 0
}
\end{laincode}

\pnum
Type parameters are evaluated entirely at compile time; they produce
no runtime code.

\begin{constraint}
  The \lain{comptime} keyword shall not appear before a parameter whose
  type is \lain{type}.  \lain{func f(comptime T type)} is ill-formed;
  write \lain{func f(T type)} instead.
\end{constraint}

\section{Compile-time value parameters}
\label{sec:gen.comptime-params}
\index{comptime parameter}

\pnum
A type's parameter list may declare a \emph{value} parameter, \lain{N usize}: a
parameter whose type is an integer type rather than \lain{type}. An instance names
its value, which shall be a constant expression (\S\,\ref{sec:decl.static-assert}): a
literal, \lain{Buf(4)}, or a module constant, \lain{Buf(SIZE)}. Each value is its own
instance, generated once. Inside the type the parameter sizes an array field,
\lain{data u8[N]}, or bounds a slice field's length, \lain{src u8[<= N]}, exactly as
the literal would. A constructor infers the value from the length of the array it is
given, or takes it first:

\begin{laincode}
SIZE usize = 16
type Buf(N usize) {
    data u8[N]
}
assert @sizeof(Buf(4)) == 4
assert @sizeof(Buf(SIZE)) == 16
func last(b Buf(4)) u8 {
    return b.data[3]                         // b.data.len is 4: proven
}
func main() i32 {
    b = Buf([1, 2, 3, 4])                    // N = 4, from the array
    c = Buf(8, [0, 0, 0, 0, 0, 0, 0, 9])     // N = 8, given
    return 0
}
\end{laincode}

\begin{constraint}
  The argument for a value parameter shall be a non-negative constant expression;
  otherwise the program is \illformed{}~(\diagcode{E124}). An array given for a field the
  parameter sizes shall have that length (\diagcode{E012}).
\end{constraint}

\begin{constraint}
  A compile-time evaluation context (CTFE) shall not call a function whose
  effect row is non-empty; only calls with an empty row are admissible. A
  violation is \illformed{}~(\diagcode{E101}).
\end{constraint}

\section{Type as value}
\label{sec:gen.type-value}
\index{type as value}

\pnum
A type declared with type parameters is a type constructor: \lain{Option(int)} names the
instance for \lain{int}, which is generated once (monomorphized) and may be used in type
annotations and variable declarations. A variant of an instance is constructed as
\lain{Option(int).Some(42)} where the declaration states the instance.  A generic struct
takes its type argument first, as a value parameter does: \lain{Box(i32, 7)} for
\lain{type Box(T type) \{ v T \}}, or \lain{Box(x)}, which infers \lain{T} from the field.

\begin{laincode}
type Option(T type) {
    Some { value T }
    None
}

func main() i32 {
    var x Option(int) = Option(int).Some(42)   // the variable states the instance
    return 0
}
\end{laincode}

\pnum
Type constructors may also be written as \lain{func} declarations returning
\lain{type}:

\begin{note}
  \textbf{Planned (not yet implemented).}  The \lain{func}-returning-\lain{type}
  spelling below is presently \diagcode{E100}; use the
  \lain{type Name(T type) \{ ... \}} form above, which is accepted. (The spelling
  \lain{type Name(T type) = type \{ ... \}} declares an alias, not a generic type: its
  instances are refused, \diagcode{E124}.)
\end{note}

\begin{laincode}
// ERROR: E100 -- the planned spelling, not yet accepted
func Option(T type) type {
    return type {
        Some { value T }
        None
    }
}
\end{laincode}

\begin{note}
  \textbf{Not yet in force.}  This implementation does not parse a function whose return type
  is \lain{type}: \lain{func Mk(T type) type} is refused at the return
  type~(\diagcode{E100}).  A generic type is declared directly, as
  \lain{type Option(T type) \{ ... \}}, which is the form the standard library uses.  The
  constraint below is retained because the form is intended, and marked because nothing
  currently checks it.
\end{note}

\begin{constraint}
  A function returning \lain{type} shall have an empty effect row: a type-level
  value cannot depend on an effect.
\end{constraint}

\section{Monomorphization}
\label{sec:gen.monomorphization}
\index{monomorphization}

\pnum
For each unique combination of comptime arguments at call sites, the
implementation produces a separate instantiation of the function.  The
name of each instantiation in the translation output is
\idbehav{determined by the implementation}.

\pnum
Monomorphization is a compile-time-only operation; at runtime, each
call site calls a specific, non-generic function.

\section{Comptime expression blocks}
\label{sec:gen.comptime-block}
\index{comptime block}

\pnum
A \lain{comptime \{ expr \}} expression evaluates \textit{expr} at compile
time.  The result is a compile-time constant that may be used as a type
annotation, array size, or parameter constraint value.

\begin{note}
  \textbf{Planned (not yet implemented).}  \lain{comptime \{ ... \}} expression
  blocks are not accepted by the reference compiler (presently
  \diagcode{E100}).  The statement form \lain{comptime if}
  (\S\,\ref{sec:gen.comptime-if}) \emph{is} available.
\end{note}

\begin{constraint}
  A \lain{comptime} expression shall be pure and terminating (i.e., it may
  only use \lain{func} calls and the constructs permitted in \lain{func}
  bodies).
\end{constraint}

\section{Comptime if}
\label{sec:gen.comptime-if}
\index{comptime if}

\pnum
\lain{comptime if cond \{ ... \} else \{ ... \}} is a compile-time
conditional.  Only the taken branch is type-checked and emitted; the other
branch is entirely discarded.  \textit{cond} shall evaluate to a
compile-time boolean constant.

\begin{note}
  \lain{comptime if} enables platform-specific code selection without
  dead-code warnings.  It is the preferred way to write code that
  varies based on compile-time parameters.
\end{note}

\section{Comptime recursion depth}
\label{sec:gen.recursion-depth}
\index{comptime recursion depth}

\pnum
The planned compile-time evaluation engine (\S\,\ref{sec:gen.comptime-params},
\S\,\ref{sec:gen.comptime-block}) will bound the recursion depth of comptime
function evaluation \idbehav{by an implementation-defined limit} and reject an
evaluation that exceeds it.  Since that engine is not yet implemented, no depth
diagnostic is currently emitted.

\section{Mode preservation in generics}
\label{sec:gen.mode-preserve}
\index{mode preservation}

\pnum
When a type parameter \lain{T} is substituted with a concrete type, the
ownership mode of the parameter is preserved.  If a parameter was declared
\lain{var T}, and \lain{T} is substituted with a type that has mode
\lain{shared} in its declaration, the substituted parameter retains the
\lain{var} mode.

\begin{note}
  This rule ensures that mode annotations in generic functions behave
  consistently regardless of the concrete type argument.
\end{note}
