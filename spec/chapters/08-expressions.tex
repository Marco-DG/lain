\chapter{Expressions}
\label{sec:08-expressions}
\index{expression}

\pnum
An expression is a syntactic construct that evaluates to a value.  Every
expression has a type, determined statically at compile time.  The grammar
production for \gramref{expression} is in Annex~A.

\pnum
Expressions are evaluated strictly left-to-right: for any binary operator
$a\ \mathit{op}\ b$ or function call \lain{f(a, b)}, the left operand
(or earlier argument) is fully evaluated before the right operand (or
later argument).

\section{Primary expressions}
\label{sec:expr.primary}
\index{primary expression}

\pnum
A primary expression is one of: an identifier, a literal, a parenthesized
expression, a block expression, an \lain{if} expression, a \lain{case}
expression, a constructor expression, or a \lain{comptime} expression.

\pnum
\textbf{Identifier expression}: evaluates to the current value of the named
variable.

\begin{constraint}
  The identifier shall be declared in scope; use of an undeclared identifier
  is \illformed{}~(\diagcode{E106}, \S\,\ref{sec:basics.resolution}).
\end{constraint}

\begin{constraint}
  The identifier shall have been initialized before use
  (\diagcode{E005}).
\end{constraint}

\section{Arithmetic operators}
\label{sec:expr.arith}
\index{arithmetic operator}

\pnum
The binary arithmetic operators are \lain{+} (addition), \lain{-}
(subtraction), \lain{*} (multiplication), \lain{/} (division), and
\lain{\%} (remainder).  Their result types are given in \S\,\ref{sec:types.rank}: \lain{+},
\lain{-}, \lain{*} and a signed \lain{/} widen so the operation cannot overflow; the forms
with an explicit policy (\lain{+\%}, \lain{/|}, \ldots, \S\,\ref{sec:types.overflow}) keep the
operand type.

\pnum
Integer division truncates toward zero.  \lain{f32}/\lain{f64} division
follows IEEE~754.

\begin{constraint}
  Integer division or remainder where the divisor is not provably non-zero (by value range
  analysis, a \lain{!= 0} refinement, or a dominating guard; \S\,\ref{sec:13-vra}) is
  \illformed{}~(\diagcode{E015}).
\end{constraint}

\begin{constraint}
  \lain{\%} shall not be applied to floating-point operands.
\end{constraint}

\pnum
The unary \lain{-} operator negates its operand.  For unsigned integer
types the result wraps modulo $2^N$.

\section{Comparison operators}
\label{sec:expr.compare}
\index{comparison operator}

\pnum
The comparison operators \lain{==}, \lain{!=}, \lain{<}, \lain{>},
\lain{<=}, \lain{>=} compare two values and yield \lain{bool}.

\begin{constraint}
  Operands of a comparison operator shall have compatible types
  (\S\,\ref{sec:types.compat}).
\end{constraint}

\begin{constraint}
  \lain{==} and \lain{!=} shall not be applied to struct types, array types,
  or enum types (\S\,\ref{sec:types.enum}).
\end{constraint}

\section{Logical operators}
\label{sec:expr.logical}
\index{logical operator}

\pnum
\lain{and} and \lain{or} are short-circuit operators: the right operand
is not evaluated if the result is determined by the left operand alone.
\lain{!} is prefix unary negation.  All yield \lain{bool}.

\begin{constraint}
  Operands of \lain{and}, \lain{or}, and \lain{!} shall have type
  \lain{bool}.
\end{constraint}

\section{Bitwise operators}
\label{sec:expr.bitwise}
\index{bitwise operator}

\pnum
The bitwise operators \lain{\&}, \lain{|}, \texttt{\textasciicircum}, \lain{<<}, \lain{>>}
operate on integer operands.  The result type is the wider operand type for
\lain{\&}, \lain{|}, \texttt{\textasciicircum}; for shift operators, the result type is
the left operand type.  A \emph{literal} shifted left by a constant expression is typed by its
value, as a constant sum is: the literal and the shift take the narrowest of its type,
\lain{i64} and \lain{u64} that holds the result, so \lain{1 << 40} is an \lain{i64} holding
\(2^{40}\), in a module assertion and in code alike.

\begin{constraint}
  Operands of bitwise operators shall be integer types.
\end{constraint}

\begin{constraint}
  The shift amount (right operand of \lain{<<} and \lain{>>}) shall
  satisfy $0 \leq \mathit{shift} < N$ where $N$ is the bit width of the
  left operand.  A shift amount that value range analysis cannot prove to be
  in range is \illformed{}~(\diagcode{E086}) --- the boundary mechanism
  (\S\,\ref{sec:vra.boundary}) that also rejects arithmetic overflow.
\end{constraint}

\begin{constraint}
  \lain{x << k} is \(x \cdot 2^k\), and like \lain{*} it shall not overflow: a left shift whose
  result value range analysis cannot prove representable in the left operand's type is
  \illformed{}~(\diagcode{E086}), for an unsigned operand as for a signed one.  No bit is
  silently shifted out.
\end{constraint}

\pnum
The \emph{wrapping} left shift \lain{x <<\% k} discards the bits shifted out, as \lain{+\%},
\lain{-\%} and \lain{*\%} wrap: its result is \(x \cdot 2^k\) modulo \(2^N\), read in the left
operand's type.  The shift amount obeys the same constraint as for \lain{<<}; an amount outside
\(0 \leq k < N\) is not a wrap.

\begin{example}
\begin{laincode}
func mix(h u32, c u8) u32 {
    return (h <<% 5) +% h +% (c as u32)     // a hash step: the high bits are meant to go
}
\end{laincode}
\end{example}

\section{The \texttt{in} operator}
\label{sec:expr.in}
\index{in operator}
\index{in guard}

\pnum
\lain{in} tests \textbf{membership in a set}, and the set is written as a range or as a list of
constants.  \lain{x in lo..hi} is \lain{true} if and only if \(\mathit{lo} \leq x < \mathit{hi}\),
and \lain{x in lo..=hi} if and only if \(\mathit{lo} \leq x \leq \mathit{hi}\); each bound is
evaluated once.  All three operands shall have integer types.

\pnum
\lain{x in [}\(e_1, \ldots, e_n\)\lain{]} is \lain{true} if and only if \(x\) equals some \(e_i\).
\(x\) is evaluated once and compared with each element in turn, as integers --- mathematically, not
after conversion to a common C type, so a \lain{u8} holding 44 does not equal 300.  Each element
shall be a \emph{closed constant}: an integer or character literal, or unary and binary arithmetic on
such literals; a name is not followed.  On the edge where the test is true, the analysis narrows
\(x\) to the \emph{hull} of the elements, \(\min e_i \leq x \leq \max e_i\) --- the test itself is
exact, but the fact recorded is the interval.  Membership in the elements of an array or slice is
not an \lain{in} expression; it is a scan.

\pnum
The indices of an array or slice \textit{arr} are the range \lain{0..arr.len}, so an index test is
written \lain{idx in 0..arr.len}.  The form \lain{idx in arr}, naming the container, was retired:
\lain{arr} is a sequence of elements and not a set of indices, and the implementation refuses it
with the range to write instead~(\diagcode{E100}).  An index refinement on a field or a parameter is
written the same way --- \lain{in 0..arr.len} for an index, \lain{in 0..=arr.len} for a cursor that
may rest at the end.

\pnum
When \lain{idx in 0..arr.len} appears as the condition of a \lain{while} or
\lain{if} statement (or as the leftmost operand of an \lain{and}-chain
condition), it establishes an \textbf{in guard}: inside the body of that
statement, the implementation shall accept \lain{arr[idx]} without
requiring further bounds verification.

\pnum
In-guards propagate through \lain{and}-chains: if the left operand of
\lain{and} establishes an in-guard, that guard is active when evaluating
the right operand.

\begin{example}
\begin{laincode}
// In-guard: arr[i] is safe without further proof
func sum(arr i32[]) i32 {
    var s i32 = 0
    var i usize = 0
    while i in 0..arr.len {
        s = s +% arr[i]   // OK: in-guarded
        i = i + 1
    }
    return s
}

// And-chain propagation:
type Lexer {
    src u8[]
    pos usize
}
func skip_to_quote(l var Lexer) {
    while l.pos in 0..l.src.len and (l.src[l.pos] as int) != '"' {
        l.pos = l.pos + 1
    }
}
\end{laincode}
\end{example}

\begin{constraint}
  An element of a membership list \lain{x in [}\ldots\lain{]} that is not a closed constant is
  \illformed{}~(\diagcode{E012}), as is a left operand that is not an integer.  An empty list is
  \illformed{}~(\diagcode{E100}).
\end{constraint}

\begin{constraint}
  An in-guard of the form \lain{idx in 0..arr.len} covers only \lain{arr[idx]}
  exactly.  Accesses \lain{arr[idx + k]} for any $k \neq 0$ are not
  covered by this guard and require separate verification or an
  \lain{unsafe} block.
\end{constraint}

\section{Cast expression (\texttt{as})}
\label{sec:expr.cast}
\index{cast expression}
\index{as operator}

\pnum
The expression \lain{expr as T} explicitly converts the value of
\textit{expr} to type \lain{T}.  An integer cast whose target cannot hold every value of the
source --- a narrowing, or a signedness change such as \lain{u32} to \lain{i32} or \lain{usize}
to \lain{i64} --- carries an \emph{overflow policy} chosen by the cast tier
(\S\,\ref{sec:types.overflow}):

\begin{longtable}{@{}lll@{}}
\toprule
\textbf{Tier} & \textbf{Form} & \textbf{On a value outside \lain{T}} \\
\midrule
\endhead
\bottomrule
\endlastfoot
proven     & \lain{as}  & narrows only if VRA proves it fits, else \diagcode{E086} \\
checked    & \lain{as?} & run-time bounds check; the \lain{else} arm on overflow \\
wrapping   & \lain{as\%}& two's-complement modular truncation \\
saturating & \lain{as|} & clamp to the minimum or maximum of \lain{T} \\
\end{longtable}

\pnum
The following casts are permitted:

\begin{longtable}{@{}lll@{}}
\toprule
\textbf{From} & \textbf{To} & \textbf{Semantics} \\
\midrule
\endfirsthead
\toprule
\textbf{From} & \textbf{To} & \textbf{Semantics} \\
\midrule
\endhead
\bottomrule
\endlastfoot
integer & integer & The same value where \lain{T} holds it; otherwise the tier's policy \\
integer & float   & Nearest representable value (IEEE~754) \\
float   & integer & Truncation toward zero \\
float   & float   & Precision change \\
pointer & pointer & Reinterpretation (\lain{unsafe} required) \\
integer & pointer & Reinterpretation (\lain{unsafe} required) \\
pointer & integer & Reinterpretation (\lain{unsafe} required) \\
\end{longtable}

\begin{constraint}
  Casts between pointer types, between a pointer and an integer, or between
  any type and a pointer shall occur only inside an \lain{unsafe} block.
  Such a cast outside \lain{unsafe} is \illformed{}~(\diagcode{E012}).
\end{constraint}

\begin{constraint}
  A cast between non-numeric, non-pointer types (e.g., struct to integer)
  is \illformed{}.
\end{constraint}

\section{Move expression (\texttt{mov})}
\label{sec:expr.mov}
\index{move expression}

\pnum
\lain{mov expr} transfers ownership of the value produced by \textit{expr}.
The source is placed in the Consumed state; any subsequent use of the
source variable is \illformed{}~(\diagcode{E001}).  See \S\,\ref{sec:11-ownership}.

\section{Borrows at call sites}
\label{sec:expr.borrow}
\index{borrow expression}

\pnum
Lain has \emph{no} prefix borrow operator (no \lain{\&}, no \lain{ref}, no
\lain{mut} expression form).  A value is borrowed simply by passing it to a
function or procedure; the borrow \emph{mode} is written at the call site,
matching the parameter's declared mode: nothing for a shared (read-only)
borrow, \lain{var} for a mutable borrow, and \lain{mov} to transfer ownership
(\S\,\ref{sec:expr.mov}).  See the call-site mode table in
\S\,\ref{sec:expr.call} and the ownership rules in \S\,\ref{sec:11-ownership}.

\section{Field access}
\label{sec:expr.field}
\index{field access}

\pnum
The expression \lain{expr.field} accesses the named field of a struct or
ADT value, or a property of an array or slice (\lain{.len}, \lain{.data}).

\begin{constraint}
  The field name shall exist on the type of \textit{expr}.
\end{constraint}

\begin{constraint}
  Writing to a field (\lain{expr.field = v}) requires \textit{expr} to be
  a mutable lvalue.
\end{constraint}

\section{Index expression}
\label{sec:expr.index}
\index{index expression}

\pnum
The expression \lain{arr[idx]} accesses the element of array or slice
\textit{arr} at integer index \textit{idx}.

\begin{constraint}
  The value range analysis shall prove $0 \leq \mathit{idx} < \mathit{arr.len}$
  at every index expression.  An index expression for which this cannot be
  proved is \illformed{}~(\diagcode{E085}).  An \lain{in} guard
  (\S\,\ref{sec:expr.in}) or an \lain{unsafe} block suppresses this
  requirement.
\end{constraint}

\section{Range index expression (sub-slicing)}
\label{sec:expr.subslice}
\index{sub-slice}
\index{range index}

\pnum
The expression \lain{arr[a..b]} produces a \textit{sub-slice}: a slice
covering elements at indices $a, a+1, \ldots, b-1$ of \lain{arr}.  The
range is \textbf{half-open}: the element at index $b$ is excluded.  The
length of the result is $b - a$.

\pnum
The inferred type of \lain{arr[a..b]} is \lain{T[b-a]}, a sized slice
type (\S\,\ref{sec:types.sized-slice}) whose length constraint records
the exact length of the result.

\begin{constraint}
  The start index \lain{a} shall satisfy $a \geq 0$.  A start index for
  which VRA cannot prove non-negativity is \illformed{}~(\diagcode{E085}).
\end{constraint}

\begin{constraint}
  The end index \lain{b} shall satisfy $b \leq \mathit{arr.len}$.  An end
  index for which VRA cannot prove this is \illformed{}~(\diagcode{E085}).
\end{constraint}

\begin{constraint}
  When both \lain{a} and \lain{b} are integer literals, the compiler
  additionally verifies $a \leq b$.  If $a > b$, the program is
  \illformed{}~(\diagcode{E087}).
\end{constraint}

\begin{example}
\begin{laincode}
var xs i32[5] = [10, 20, 30, 40, 50]
var s = xs[1..4]      // type i32[3]; covers indices 1, 2, 3
var e = xs[3..3]      // OK: empty sub-slice, length 0
// var bad = xs[5..2] // [E087]: 5 > 2 (literal ordering violated)
\end{laincode}
\end{example}

\section{Function call}
\label{sec:expr.call}
\index{function call}

\pnum
A function call expression \lain{f(args)} evaluates the arguments and
transfers control to the callee.  Arguments are evaluated left-to-right.

\pnum
Argument ownership modes shall be given explicitly at the call site:

\begin{longtable}{@{}ll@{}}
\toprule
\textbf{Syntax} & \textbf{Meaning} \\
\midrule
\endfirsthead
\toprule
\textbf{Syntax} & \textbf{Meaning} \\
\midrule
\endhead
\bottomrule
\endlastfoot
\lain{f(x)}     & shared borrow (default; parameter declared with no mode keyword) \\
\lain{f(var x)} & mutable borrow (parameter declared \lain{var}) \\
\lain{f(mov x)} & ownership transfer (parameter declared \lain{mov}) \\
\end{longtable}

\begin{constraint}
  The mode annotation at the call site shall match the declared parameter
  mode.  A mismatch is \illformed{}.
\end{constraint}

\begin{constraint}
  The number of arguments shall equal the number of parameters (unless the
  callee is a variadic C function declared with \lain{...}).
\end{constraint}

\pnum
\textbf{Two-phase borrows}: during argument evaluation, borrows of the
receiver of a method call are placed in the RESERVED phase and promoted to
ACTIVE after all arguments are evaluated
(see \S\,\ref{sec:11-ownership}).

\section{Block expression}
\label{sec:expr.block}
\index{block expression}

\pnum
A block expression \texttt{\{ stmts... expr \}} evaluates each statement
in order, then evaluates the final expression, whose value is the value of
the block.  If the final expression is absent, the block has no value.

\section{If expression}
\label{sec:expr.if}
\index{if expression}

\pnum
An \lain{if} expression of the form
\lain{if cond \{ e1 \} else \{ e2 \}} evaluates \textit{cond}; if true,
evaluates $e_1$; otherwise, evaluates $e_2$.

\begin{note}
  \textbf{Not yet in force.}  This implementation does not parse an \lain{if} in
  expression position: \lain{x = if b \{ 1 \} else \{ 2 \}} is refused at the
  \lain{if}~(\diagcode{E100}).  The two constraints below therefore describe a form no
  implementation currently accepts, and nothing checks them.  They are retained because the
  form is intended; they are marked so that a reader does not take them for requirements an
  implementation is meeting.  The \lain{if} \emph{statement} is
  \S\,\ref{sec:stmt.if}, and is unaffected.
\end{note}

\begin{constraint}
  The types of $e_1$ and $e_2$ shall be compatible.  If they are not, the
  expression is \illformed{}.
\end{constraint}

\begin{constraint}
  \textit{cond} shall have type \lain{bool}, or an integer type, or an optional that
  narrows (\S\,\ref{sec:types.bool}).
\end{constraint}

\section{Match expression (\texttt{case})}
\label{sec:expr.match}
\index{case expression}

\pnum
A \lain{case} expression (\gramref{match-expression}) selects one of
several alternatives based on pattern matching.  All arms shall produce
values of compatible types; the type of the \lain{case} expression is that
common type.  See \S\,\ref{sec:15-match} for full exhaustiveness rules.

\section{Constructor expression}
\label{sec:expr.constructor}
\index{constructor expression}

\pnum
A constructor expression builds a value of a struct or ADT type by
supplying all field values.  See \S\,\ref{sec:types.struct} and
\S\,\ref{sec:types.adt} for constructor rules.

\section{Compound assignment}
\label{sec:expr.compound-assign}
\index{compound assignment}

\pnum
Compound assignment \lain{x op= e} is syntactic sugar for
\lain{x = x op e}.  The left-hand side shall be a mutable lvalue.
All compound forms of the arithmetic and bitwise operators are supported
(see \S\,\ref{sec:lex.operators}).
