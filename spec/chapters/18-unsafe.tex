\chapter{Unsafe code}
\label{sec:18-unsafe}
\index{unsafe code}

\section{Purpose}
\label{sec:unsafe.purpose}

\pnum
The \lain{unsafe} block provides a controlled escape hatch for operations
that a conforming implementation cannot statically verify.  Unsafe blocks
are explicitly delimited in the source text and are therefore auditable.
Unsafe code cannot accidentally spread outside the enclosing block.

\section{Syntax}
\label{sec:unsafe.syntax}

\pnum
An unsafe block is written as \lain{unsafe \{ body \}}.  It may appear
wherever a statement is valid (\S\,\ref{sec:stmt.unsafe}).

\section{What unsafe enables}
\label{sec:unsafe.enables}
\index{unsafe!what it enables}

\pnum
Inside an \lain{unsafe} block, the following operations are permitted:

\begin{enumerate}
  \item \textbf{Raw pointer dereference}: \lain{*ptr} reads the value
        pointed to by a raw pointer; \lain{*ptr = v} writes through a
        writable raw pointer \lain{*var T}. A \lain{*T} is read-only: a write through it
        --- \lain{*p = v}, \lain{p.f = v}, \lain{@store(p, i, v)} --- is \illformed{} here
        too~(\diagcode{E009}), and a \lain{*T} does not convert implicitly to a
        \lain{*var T}~(\diagcode{E012}). A \lain{*T} becomes writable only by an explicit
        cast inside \lain{unsafe}, \lain{p as *var T}, which asserts that writing through it
        is valid.
  \item \textbf{Address-of}: \lain{\&x} creates a raw pointer to the
        storage of \lain{x}: a \lain{*var T} when the program may write \lain{x} (a
        \lain{var} binding or parameter, an element or field of one, or what a \lain{*var}
        pointer points to), and a \lain{*T} otherwise.
  \item \textbf{Indexing}: a raw pointer has no length and cannot be indexed
        (\diagcode{E012}); read through it with \lain{*p}, or \lain{@load} a vector.
  \item \textbf{Pointer and integer casts}: \lain{p as *T},
        \lain{n as *T}, \lain{p as usize}, etc., except a cast that views the bytes of a struct,
        or of a sum's payload, whose storage order the compiler chooses, which stays
        \illformed{}~(\diagcode{E012}; \S\,\ref{sec:types.struct}): mark it \tok{[ordered]}.
  \item \textbf{Direct ADT field access}: reading a variant's field with the
        qualified form \lain{value.Variant.field} without going through a
        \lain{case} arm.  Outside \lain{unsafe} this is
        \illformed{}~(\diagcode{E125}); the safe idiom is to destructure with
        \lain{case}.
  \item \textbf{Bounds-check suppression}: array indexing inside an
        \lain{unsafe} block does not require a VRA proof (the
        programmer asserts the access is in bounds).
  \item \textbf{Numeric-obligation suppression}: an integer operation inside an
        \lain{unsafe} block does not require a proof that it cannot overflow or that a
        narrowing fits~(\diagcode{E086}), that a divisor is not zero~(\diagcode{E015}), or that a
        shift amount is below the width. A narrowing that does not fit, whether an explicit
        \lain{as} or the implicit one where a value is stored, passed, returned or placed in a
        constructor, yields the value modulo $2^N$ for an $N$-bit target, as C17's conversion
        does, and the analysis of the code after the block reasons from that value: with
        \lain{var y u16 = 260}, \lain{unsafe \{ x = y as u8 \}} leaves \lain{x} equal to 4.
\end{enumerate}

\pnum
The index below is proven from the wrapped value, 4, in the safe code after the block:

\begin{laincode}
// VERIFY: exit 5
func main() i32 {
    var a i32[8] = [1, 2, 3, 4, 5, 6, 7, 8]
    var y u16 = 260
    var x u8 = 0
    unsafe {
        x = y as u8
    }
    return a[x]
}
\end{laincode}

\section{What unsafe does NOT disable}
\label{sec:unsafe.not-disabled}
\index{unsafe!what it does not disable}

\pnum
The following safety features remain active inside \lain{unsafe} blocks:

\toprule
\textbf{Feature} & \textbf{Disabled by \lain{unsafe}?} \\
\midrule
\endfirsthead
\toprule
\textbf{Feature} & \textbf{Disabled by \lain{unsafe}?} \\
\midrule
\endhead
\bottomrule
\endlastfoot
Pointer dereference (\diagcode{E060})     & \textbf{Yes} \\
Pointer/integer casts (\diagcode{E012})   & \textbf{Yes} \\
Direct ADT field access (\diagcode{E125}) & \textbf{Yes} \\
Bounds check requirement (\diagcode{E085}) & \textbf{Yes} \\
Ownership tracking (\diagcode{E001}--\diagcode{E007}) & No \\
Borrow checking (\diagcode{E004})    & No \\
Move semantics                       & No \\
Type checking                        & No \\
Overflow and narrowing check (\diagcode{E086}) & \textbf{Yes} \\
Division-by-zero check (\diagcode{E015}) & \textbf{Yes} \\
Exhaustiveness checking (\diagcode{E014}) & No \\
Purity enforcement (\diagcode{E011}) & No \\
\end{longtable}

\begin{constraint}
  Ownership and linearity rules (\S\,\ref{sec:11-ownership}) are not
  suspended inside \lain{unsafe} blocks.  Use-after-move, double-move,
  and borrow conflicts are still constraint violations inside
  \lain{unsafe}~(\diagcode{E001}--\diagcode{E007}).
\end{constraint}

\section{Undefined behavior in unsafe}
\label{sec:unsafe.ub}
\index{undefined behavior!in unsafe}

\pnum
The following operations inside an \lain{unsafe} block may produce
\undefbehav{undefined behavior if the programmer's safety assertion is
incorrect}:

\begin{itemize}
  \item Dereferencing a null pointer.
  \item Dereferencing a pointer to freed or uninitialized memory.
  \item Writing to memory through a pointer derived from a read-only
        (shared) source.
  \item Accessing an array element with an out-of-range index.
  \item Dividing or taking a remainder by zero, shifting by an amount outside $[0, N)$ for an
        $N$-bit operand, or a signed arithmetic result that does not fit its type (operands
        narrower than 64 bits are computed wider, so only a 64-bit one can).
  \item Accessing a field of an ADT through a tag that does not match
        the active variant.
  \item Writing into an enumeration's storage a value that is none of its
        variants (\lain{*(\&k as *var u8) = 3} over \lain{type K u8 \{ A, B, C \}}): a sum
        that stores its payload-less variants in the enumeration's spare values reads it as
        one of those (\S\,\ref{sec:mem.adt-layout}).
  \item Writing into a tagged sum's tag a value that is none of its variants: no
        \lain{case} arm matches it.
\end{itemize}

\pnum
A conforming implementation that generates C99 translation output inherits
the undefined behavior rules of ISO/IEC~9899 (C17) for operations within
\lain{unsafe} blocks.

\section{Borrow scope for unsafe blocks}
\label{sec:unsafe.borrow-scope}

\pnum
An \lain{unsafe} block is a regular block scope for the purposes of borrow
checking.  Borrows registered within the block are released on block exit,
and the borrow checker's invariants hold at the block boundaries.

\section{Nesting}
\label{sec:unsafe.nesting}

\pnum
\lain{unsafe} blocks may be nested.  The inner block does not extend the
permissions of the outer block beyond what is already enabled.
\idbehav{Whether the implementation issues a diagnostic for redundant nested
unsafe blocks is implementation-defined}.
