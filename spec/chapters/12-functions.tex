\chapter{Functions and effects}
\label{sec:12-functions}
\index{function}

\section{The effect row}
\label{sec:fn.distinction}
\index{effect row}

\pnum
A function has one introducer, \lain{func}, and an \textbf{effect row}: a set drawn
from \lain{io}, \lain{diverge}, \lain{raises} and \lain{alloc}.  The row is
inferred from the body across the call graph, its default is $\emptyset$ --- pure
and total --- and an \lain{effects} clause widens that default for a function that
deviates.  The row is a \emph{complete} upper bound: an effect the body has and the
row does not name is \illformed{}, so a caller may rely on what it reads
(\S\,\ref{sec:fn.purity}).

\begin{longtable}{@{}lll@{}}
\toprule
\textbf{Property} & \textbf{default row ($\emptyset$)} & \textbf{with the effect named} \\
\midrule
\endfirsthead
\toprule
\textbf{Property} & \textbf{default row ($\emptyset$)} & \textbf{with the effect named} \\
\midrule
\endhead
\bottomrule
\endlastfoot
Observable side effects           & forbidden          & \lain{effects io} \\
Allocation                        & forbidden          & \lain{effects alloc} \\
\lain{panic}                      & forbidden          & \lain{effects raises} \\
Unbounded \lain{while}            & forbidden          & \lain{effects diverge} \\
Bounded \lain{while decreasing}   & allowed            & allowed \\
\lain{for} loops                  & allowed            & allowed \\
Direct recursion (with measure)   & allowed            & allowed \\
Recursion through several functions & allowed when ranked (\S\,\ref{sec:fn.purity}) & allowed \\
Global mutable state              & does not exist in the language & --- \\
Termination guarantee             & yes                & waived by \lain{diverge} only \\
\end{longtable}

\pnum
Naming an effect is not a local suppression.  It enters this function's row, which
is what every caller reads, so the acknowledgement propagates outward until some
function is genuinely entitled to it.

\begin{note}
  \lain{proc} was the form in which the introducer granted the effects instead of
  the row.  It has been removed (\S\,\ref{sec:decl.proc}); the row is the only
  mechanism.
\end{note}

\pnum
A \lain{func} is referentially transparent: calling it with the same
arguments always produces the same result.  Its evaluation has no
observable effect on any state outside its own stack frame.

\pnum
Local mutation through a \lain{var T} parameter (exclusive mutable
borrow) is permitted in a \lain{func}. The borrow checker guarantees
no aliasing, so the mutation is observable only through the
parameter binding itself; the function remains deterministic and
referentially transparent (same input borrow $\Rightarrow$ same
mutation pattern).

\begin{example}
\begin{laincode}
type Counter { val i32 }

func increment(var c Counter) {  // legal: mutation is local
    c.val = c.val +% 1
}
\end{laincode}
\end{example}

\pnum
\diagcode{W130} advised downgrading an effect-free \lain{proc} to a \lain{func}.
It was removed with the form it advised against: a warning whose subject cannot be
written is dead weight that still has to be kept correct --- and it had just been
caught stating the opposite of the truth, because its eligibility test read the
callee's \emph{keyword} rather than the callee's row.

\section{Purity enforcement}
\label{sec:fn.purity}
\index{purity enforcement}

\begin{constraint}
  A function that calls one whose effect row names an effect its own row does not
  is \illformed{}~(\diagcode{E011}).  The callee's introducer plays no part: the
  effect is what is refused.  Effects are transitive, so this reaches a callee
  three layers down that a rule about direct calls would miss.
\end{constraint}

\begin{constraint}
  A function that contains a \lain{while} loop whose termination the
  implementation can neither verify from an explicit \lain{decreasing} measure
  nor establish by inferring one (\S\,\ref{sec:stmt.while.infer}) is
  \illformed{}~(\diagcode{E011}) \emph{unless its row names} \lain{diverge}.
  Naming it is not a suppression: \lain{diverge} enters this function's row and
  every caller must acknowledge it in turn.  A caller that does not is \illformed{}:
  \diagcode{E011} when it states no row, and \diagcode{E130} when its written row omits
  \lain{diverge}.
\end{constraint}

\begin{laincode}
func spin(x i32) i32 effects diverge {
    var y i32 = x
    while y != 0 { y = y }
    return y
}

func g(x i32) i32 {
    return spin(x)        // ERROR [E011]: g states no row, and spin may not return
}
\end{laincode}

\begin{constraint}
  A \lain{func} that calls itself directly is permitted only if it carries a
  well-founded \lain{decreasing} measure --- supplied explicitly or inferred
  by the implementation (\S\,\ref{sec:fn.termination}).  A directly-recursive
  \lain{func} with no measure and none inferable is
  \illformed{}~(\diagcode{E011}); one whose measure is malformed is reported
  \diagcode{E091}, and one whose measure is not provably decreasing and
  non-negative at every self-call is reported \diagcode{E082}.
\end{constraint}

\begin{constraint}
  A function whose row does not name \lain{diverge}, and that lies on a recursion cycle with
  at least one \emph{other} function, owes termination over that cycle.  The unit is its
  \emph{component}: every function it calls, directly or through others, that calls it back.
  Each function of the component needs a \emph{measure}, written with \lain{decreasing} or
  inferred by the implementation, such that
  \begin{enumerate}
    \item at every call from a function of the component to a function of the component,
          self-calls included, the callee's measure of the arguments passed is at most the
          caller's measure there, and the caller's measure is at least 0 there (an unsigned
          type, or a guard that implies it); and
    \item every cycle of calls inside the component, of any length and through any of its
          calls, contains at least one call at which it is strictly smaller.
  \end{enumerate}
  Written measures that satisfy both from the facts available at the calls
  (\S\,\ref{sec:vra.fragment}) shall be accepted; inferring a measure is beyond the guarantee.
  A component with no such measure is \illformed{}, reported at a call on a cycle of the
  component where the measure is not shown to fall: \diagcode{E011}, or \diagcode{E082} when
  that function has a written \lain{decreasing} clause.
\end{constraint}

\begin{note}
  An implementation may refuse a component beyond the capacity of its proof search, with a
  diagnostic saying so.  A measure of several parts compared in order is not available for a
  cycle through several functions, written or inferred; such a function states
  \lain{effects diverge}.  A self-recursive function on no cycle with another
  keeps the rule of \S\,\ref{sec:fn.termination}.  A call through a function pointer is, for
  this purpose, a call to every function of the program whose address is taken and whose
  parameter count matches.  An \lain{extern} that calls back into the program is outside the
  proof: its row is believed, as every \lain{extern}'s is.
\end{note}

\begin{laincode}
// VERIFY: exit 0
func a(n u8) u8 {
    if n == 0 { return 0 }
    return b(n - 1)              // falls here
}

func b(n u8) u8 {
    return c(n)                  // not here: one fall per way round is enough
}

func c(n u8) u8 {
    if n == 0 { return 0 }
    return a(n - 1)
}

func main() i32 {
    if a(9) != 0 { return 1 }
    return 0
}
\end{laincode}

The same cycle with its measure written is guaranteed: \lain{n} is no greater at every call
and smaller at one call on every way round.

\begin{laincode}
// VERIFY: exit 0
func a(n u8) u8 decreasing n {
    if n == 0 { return 0 }
    return b(n - 1)              // falls here
}

func b(n u8) u8 decreasing n {
    return c(n)                  // no greater here, which is enough
}

func c(n u8) u8 decreasing n {
    if n == 0 { return 0 }
    return a(n - 1)
}

func main() i32 {
    if a(9) != 0 { return 1 }
    return 0
}
\end{laincode}

\begin{laincode}
func ping(n u8) u8 {
    return pong(n)               // ERROR [E011]: n never falls, so the cycle may not end
}

func pong(n u8) u8 {
    return ping(n)
}
\end{laincode}

\begin{note}
  Generic functions (\lain{func} with \lain{type} parameters) are
  excluded from mutual-recursion detection until they are monomorphized.
\end{note}

\section{Termination analysis}
\label{sec:fn.termination}
\index{termination analysis}

\pnum
A \lain{func} is guaranteed to terminate because:
\begin{enumerate}
  \item every \lain{while} loop carries a verified termination measure,
        supplied explicitly or inferred (\S\,\ref{sec:stmt.while.infer});
  \item \lain{for} loops iterate over finite ranges;
  \item every direct self-call strictly decreases a well-founded measure, and a
        recursion cycle through several functions is ranked by one measure per function
        (\S\,\ref{sec:fn.purity}).
\end{enumerate}

\pnum
\textbf{Recursion measure.}  The measure for a directly-recursive \lain{func}
is a parameter (\lain{decreasing n}) or a difference of two parameters
(\lain{decreasing hi - lo}).  When omitted, the implementation may infer one.  An inferred
measure is beyond the guarantee (\S\,\ref{sec:vra.fragment}), and it may be one no
\lain{decreasing} clause can state, such as the pair $(m, n)$ compared in order that makes
Ackermann's function end.

\pnum
A measure, written or inferred, is checked at every call from a function of its recursion
component to a function of that component, the function itself included
(\S\,\ref{sec:fn.purity}), under the facts that hold at the call, as a loop's measure is checked
on each iteration.  At each such call the caller's measure shall be well-defined and
non-negative, and the measure of the callee's arguments shall be well-defined and no greater
than the caller's; every cycle of such calls shall contain one at which it is strictly smaller.
A function that recurses only on itself makes a cycle at each self-call, so each self-call shall
make its measure strictly smaller.  A call that breaks this is \illformed{}: \diagcode{E082}
when the measure was written, \diagcode{E011} otherwise.  ``Well-defined'' means that the
measure's arithmetic is free of overflow there, as any expression's must be.

\begin{laincode}
func f(n i32, k i32 >= 0) i32 decreasing k {
    if n <= 0 { return 0 }
    return f(n - 1, k)    // ERROR [E082]
}

func main() i32 {
    return f(3, 5)
}
\end{laincode}

\begin{laincode}
// VERIFY: exit 0
func down(k i32 >= 0) i32 decreasing k {
    if k <= 0 { return 0 }
    return down(k - 1)
}

func main() i32 {
    if down(3) != 0 { return 1 }
    return 0
}
\end{laincode}

\pnum
No termination analysis is performed for a function whose row names \lain{diverge}.

\section{Universal Function Call Syntax (UFCS)}
\label{sec:fn.ufcs}
\index{UFCS}

\pnum
An expression of the form \lain{x.f(args)} is desugared to \lain{f(x, args)}
before name resolution, provided \lain{f} is not a declared field of
\lain{x}'s type.  This is called Universal Function Call Syntax (UFCS).

\pnum
\textbf{UFCS ownership}: the ownership mode of the first argument in the
desugared call is determined by the declared mode of the first parameter of
\lain{f}:

\begin{itemize}
  \item If the first parameter is \lain{var}, the receiver is automatically
        mutably borrowed: \lain{x.f()} desugars to \lain{f(var x)}.
  \item If the first parameter is \lain{mov}, the receiver is moved:
        \lain{x.f()} desugars to \lain{f(mov x)}.  A \emph{linear} receiver's move shall
        be written, as every transfer of a linear value is (\diagcode{E007}): call
        \lain{f(mov x)}.
  \item If the first parameter is shared (default), the receiver is shared:
        \lain{x.f()} desugars to \lain{f(x)}.
\end{itemize}

\pnum
\textbf{UFCS resolution algorithm}:
\begin{enumerate}
  \item Check if \lain{f} is a declared field of \lain{x}'s type.  If so,
        this is a field access, not UFCS.
  \item Search for a function named \lain{f} whose first parameter type is
        compatible with the type of \lain{x}.
  \item If found, desugar the call.
  \item If no matching function is found, the call is unresolved and the
        program is \illformed{} (an unresolved receiver or callee is reported;
        a bare undeclared identifier is \diagcode{E106},
        \S\,\ref{sec:basics.resolution}).
\end{enumerate}

\begin{example}
\begin{laincode}
func is_empty(s u8[]) bool { return s.len == 0 }

func main() i32 {
    var buf = "hello"
    var empty = buf.is_empty()   // desugars to: is_empty(buf)
    if empty { return 1 }
    return 0
}
\end{laincode}
\end{example}

\section{Calling conventions}
\label{sec:fn.abi}
\index{calling convention}

\pnum
The calling convention for Lain functions corresponds to the C99 calling
convention of the target platform, as determined by the C compiler used for
the translation output.  The parameter passing rules are:

\begin{longtable}{@{}p{3.6cm}p{3.6cm}p{6.8cm}@{}}
\toprule
\textbf{Lain parameter} & \textbf{C type} & \textbf{Semantics} \\
\midrule
\endfirsthead
\toprule
\textbf{Lain parameter} & \textbf{C type} & \textbf{Semantics} \\
\midrule
\endhead
\bottomrule
\endlastfoot
shared struct \lain{T} & \texttt{T * restrict} & pointer to the caller's value, read only \\
\lain{var} struct \lain{T} & \texttt{T * restrict} & pointer to the caller's value \\
\lain{mov} struct \lain{T} & \texttt{T}        & by value (bitwise copy) \\
shared or \lain{mov} primitive & \texttt{T}   & by value \\
\lain{var} primitive    & \texttt{T*}       & pointer to the caller's value \\
slice \lain{T[]}        & \texttt{size\_t}, \texttt{T*} & two parameters, the length first \\
\end{longtable}

\section{Return values}
\label{sec:fn.return}
\index{return value}

\pnum
A return statement has the form \lain{return <expr>}.  The mode of the
returned value is determined by the function's declared return type and
follows the same rules as call-site argument passing.

\pnum
A \lain{return} may be prefixed with \lain{mov} or \lain{var}:
\lain{return mov x} makes the ownership transfer explicit, and
\lain{return var x} returns a mutable borrow (the pattern for a \lain{func}
whose declared return type is \lain{var T}).  When the return type is owned,
a bare \lain{return expr} already moves \lain{expr}, so \lain{mov} is optional
there.

\begin{note}
  Returning a borrow of a \emph{local} variable is \illformed{}~(\diagcode{E010}); the rule on
  references outliving their storage is stated in full at \S\,\ref{sec:mem.storage}.  This
  supersedes an earlier design (Q-009) in which explicit \lain{mov}/\lain{var} in return
  position was rejected.
\end{note}


\section{Function pointers}
\label{sec:fn.pointer}
\index{function pointer}

\pnum
A function used as a value has a function-pointer type, \lain{*func(P) R} with the function's
effect row (\S\,\ref{sec:fn.distinction}).  It converts to a function-pointer type wherever a
value converts: an initializer, an assignment, an argument, a return value, a struct field or a
sum payload.  The function shall have as many parameters as the pointer type, the same parameter
and return types apart from their refinements, and an effect row contained in the pointer type's,
so that it does no more than the pointer admits; otherwise the program is
\illformed{}~(\diagcode{E122}).

\pnum
The function assumes its parameters' constraints on entry, and a call through the pointer relies on
the pointer type's return type.  So the function converts only if every argument a call through
the pointer can pass is one the function admits, and every result the function can return is one
the pointer type admits; otherwise the program is \illformed{}~(\diagcode{E122}).  In particular:
\begin{itemize}
  \item A constraint written on a parameter itself, a value constraint such as \lain{b i32 > 0}
        (\S\,\ref{sec:vra.constraints}) or a length constraint such as \lain{a u8[>= 4]}
        (\S\,\ref{sec:types.sized-slice}), cannot be stated by a function-pointer type, so a
        function with one never converts.
  \item A parameter of a refined type alias (\S\,\ref{sec:types.alias-refinement}) is admitted when
        the pointer type's parameter admits no value the alias excludes.  With
        \lain{type Small = i32 >= 1}, a function taking \lain{Small} converts to
        \lain{*func(Small) i32}, and to \lain{*func(Pos) i32} with
        \lain{type Pos = i32 >= 1 and <= 9}, but not to \lain{*func(i32) i32}.
  \item A refined return type in the pointer type shall be guaranteed by the function's return
        type or return constraint: \lain{func two() i32 >= 1} converts to \lain{*func() Small},
        and a function returning a plain \lain{i32} does not.  A pointer type whose return type is
        not refined accepts any function, and a call through it gets that type's range.
  \item A function-pointer value converting to another function-pointer type obeys the same
        rules.  A parameter or return that is itself a function pointer shall have the same type
        in both, its refinements and effect row included.
\end{itemize}

\begin{laincode}
func safe_div(a i32, b i32 > 0) i32 { return a / b }

func main() i32 {
    var f *func(i32, i32) i32 = safe_div    // ERROR [E122]
    return f(10, 2)
}
\end{laincode}

\begin{laincode}
type Small = i32 >= 1

func inv(b Small) i32 { return 100 / b }

func main() i32 {
    var g *func(i32) i32 = inv    // ERROR [E122]
    return g(4)
}
\end{laincode}

\begin{laincode}
type Pos = i32 >= 1 and <= 9

func zero() i32 { return 0 }

func main() i32 {
    var g *func() Pos = zero    // ERROR [E122]
    return 100 / g()
}
\end{laincode}

\pnum
To call a function with a constrained parameter through a pointer, wrap it in a function whose
parameters are not constrained, which tests the condition and calls it directly.  The example
also converts a return constraint and an alias parameter, both of which the pointer types state:

\begin{laincode}
// VERIFY: exit 30
type Small = i32 >= 1
type Pos = i32 >= 1 and <= 9

func safe_div(a i32, b i32 > 0) i32 { return a / b }

func div_or_zero(a i32, b i32) i32 {
    if b > 0 { return safe_div(a, b) }
    return 0
}

func inv(b Small) i32 { return 100 / b }

func two() i32 >= 1 { return 2 }

func main() i32 {
    var f *func(i32, i32) i32 = div_or_zero
    var g *func() Small = two
    var h *func(Pos) i32 = inv
    q = f(10, g())
    r = h(4)
    if q != 5 { return 1 }
    if r != 25 { return 2 }
    return 30
}
\end{laincode}

\pnum
A function that takes a callback converts when the two callback types are the same:

\begin{laincode}
// VERIFY: exit 6
func inc(x i32) i32 { return x +% 1 }

func apply(f *func(i32) i32, x i32) i32 { return f(x) }

func main() i32 {
    var g *func(*func(i32) i32, i32) i32 = apply
    if g(inc, 5) != 6 { return 1 }
    return 6
}
\end{laincode}

\section{The \texttt{panic} builtin}
\label{sec:fn.panic}
\index{panic}

\pnum
\lain{panic(msg)} is a builtin expression that terminates program
execution immediately.  Its type is \textit{Never} (the bottom type:
a subtype of every type).  Because it does not return, \lain{panic}
may appear in any expression position---including as the body of a
match arm whose declared type is otherwise unrelated.

\pnum
A call to \lain{panic} is the \lain{raises} effect: it is permitted in a function whose
row names \lain{raises}, and elsewhere \illformed{}~(\diagcode{E011}).  Like every effect,
it enters the row of each caller in turn.

\begin{constraint}
  \textbf{Q-014, S16.}
  When \lain{panic} is executed, the program terminates immediately
  via the platform abort primitive.  No \lain{defer} block is
  executed.  No stack unwinding occurs.
\end{constraint}

\begin{note}
  The reference implementation emits, for \lain{panic(msg)}, the
  equivalent of
  \texttt{fprintf(stderr, "panic: \%.*s\textbackslash{}n", ...) ; abort()}.
  The message is written to the standard error stream before abort.
\end{note}

\begin{example}
\begin{laincode}
func head(s u8[]) u8 effects raises {
    if s.len == 0 {
        panic("empty slice")    // Never; satisfies the return type
    }
    return s[0]
}
\end{laincode}
\end{example}

\section{Function attributes}
\label{sec:fn.attributes}
\index{attribute}

\pnum
A function declaration may be prefixed with one or more attributes
(\S\,\ref{sec:decl.attributes}).  The attributes applicable to
functions in version~1.0 are:

\begin{itemize}
  \item \tok{[private]} --- module-private visibility
        (\S\,\ref{sec:mod.visibility}).
  \item \tok{[cold]}, \tok{[hot]} --- a hint to the C compiler that the function runs
        rarely, or often.
  \item \tok{[noreturn]} --- the function never returns, which is checked on a body
        (\diagcode{E135}) and believed on an \lain{extern}.
\end{itemize}
Table~\ref{tab:attributes} lists every attribute and where it applies.

\pnum
Floating-point operations are never contracted.  In \lain{a * b + c} the product is rounded
before it is added, as two IEEE~754 operations, in every function, so a result does not depend on
whether the target has a fused multiply-add.

\begin{constraint}
  No function opts out of this.  The attribute \tok{[fast\_math]} is
  \illformed{}~(\diagcode{E103}).
\end{constraint}

\begin{laincode}
[fast_math]                     // ERROR [E103]: floating point is never contracted
func square(a f64) f64 {
    return a * a
}
\end{laincode}

\begin{note}
  The reference implementation emits, after the includes of a module that computes in floating
  point, \texttt{\#pragma GCC optimize ("fp-contract=off")} for GCC and
  \texttt{\#pragma STDC FP\_CONTRACT OFF} for clang; a module with no floating point gets
  neither.  Without them, GNU C's default \texttt{-ffp-contract=fast} fuses a multiply and an add
  across statements under \texttt{-mfma} or \texttt{-march=native}.  One case is outside the
  guarantee: clang given an explicit \texttt{-ffp-contract=fast} disregards the pragma, by its
  design.
\end{note}
